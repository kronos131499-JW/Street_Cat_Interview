# 编辑台 UI 接入说明（供 AI 编程助手使用）

本文对应 `editor_ui_components.zip`，参考图是 `05_reference/reference_with_text.png`。目标是在现有项目里还原这套手绘纸张界面，并接回已有写稿逻辑。先阅读项目现有 UI、路由、数据和字体配置，再实施。本文没有假定项目使用 Unity、Ren’Py、Godot 或网页框架。

## 1. 先遵守这些约束

- 参考尺寸为 **1678 × 937**，以本包坐标为准。不要套用其他界面的 1536 × 1024 尺寸。
- 保留原有暖米色纸纹、棕色文字、陶红强调色和手绘边框，不重画成通用网页卡片。
- 实际运行优先使用 `02_without_text`，文字由项目自己的文本组件渲染。有字版用于快速预览、对照和确实不需要动态变化的区域。
- **无字版只去掉了文字，并不是完全空白底板。** 面板里的圆圈、图标、下划线、选中勾号和装饰多数已经画在图片里。
- **大面板与内部裁片是不同使用粒度，不能全部堆叠。** 默认只放完整无字面板和四个独立按钮，再加动态文字与透明交互区。
- 保留已有选材、预览、修改和审核逻辑。图上的 `0/10`、`0/4` 是展示状态，不足以确定全部游戏规则；不要据此擅自更改最低卡数、审核条件或消耗规则。
- 本包是从效果图拆出的位图素材，不是源工程分层文件。需要去掉已烘焙的装饰时，应补干净底图，不能假装某个图标已能独立隐藏。

## 3. 坐标、留白和缩放

所有坐标从参考画布左上角开始，x 向右、y 向下。`source_rect = [x, y, width, height]` 表示裁切区域；25 组组件的 PNG 四边各增加 **4 px 透明留白**。

因此放置整张 PNG 时：

```text
imageLeft = x - 4
imageTop  = y - 4
imageWidth  = width + 8
imageHeight = height + 8
```

不要使用 `(x, y)` 放置含留白的 PNG，否则整组内容会向右下偏 4 px。不要为了消除这 4 px 自动裁透明边；裁掉后必须同步修改坐标和尺寸。

以提交按钮为例：原区域 `[1170, 827, 453, 73]`，导出 PNG 为 `461 × 81`，放置坐标为 `(1166, 823)`。有字版与无字版使用完全相同的 Rect。

适配不同窗口时，先创建 1678 × 937 的虚拟根画布，整组等比缩放并居中：

```text
scale = min(availableWidth / 1678, availableHeight / 937)
offsetX = safeLeft + (availableWidth  - 1678 * scale) / 2
offsetY = safeTop  + (availableHeight -  937 * scale) / 2
screenX = offsetX + imageLeft * scale
screenY = offsetY + imageTop  * scale
```

`availableWidth/Height` 是扣除安全区后的尺寸。鼠标或触摸坐标用逆变换映射回虚拟画布；布局、文字和点击区域采用同一个比例。暂不做窄屏重新排版，也不让左右两列分别拉伸。

如果引擎使用中心锚点，对同一导出图使用 `(x - 4 + exportWidth/2, y - 4 + exportHeight/2)` 作为参考中心。若 y 轴向上，再按该引擎根坐标系转换；不要在未知 Canvas 配置下直接套用世界坐标。

- 使用 `01_article_panel` 后，不再常态叠加 `02`、`03`、`04`、`05`、`22`、`23`、`24`；它们是同一块图的局部裁片。

- 来源图标已在无字稿纸中保留。独立 `source_*_original` 是备用素材。
- 三个无字标题的红色编号底仍存在。默认直接在圆心写 `1`、`2`、`3`，不再盖一个新的红色徽章。

## 8. 点击区域与状态接入

四个底部按钮的点击区使用各自 `source_rect`，不把透明留白算进视觉边框。写作方向的点击区分别使用 `09`、`10` 的原图区域。装饰纸板、夹子和来源图例默认不接收输入；来源图例在原图中是说明，不要擅自变成筛选器。

| 控件 | 接入现有行为 | 保持的数据 |
| --- | --- | --- |
| 返回重选素材 | 打开已有选材页面或返回对应步骤 | 保留当前选择；草稿修改的保留策略沿用项目实现 |
| 预览文章 | 打开现有文章预览 | 使用当前草稿，不偷偷提交审核 |
| 编辑关键表述 | 打开现有编辑界面 | 编辑后回写现有草稿模型 |
| 提交审核 | 调用现有校验和审核入口 | 避免重复提交；加载和错误状态沿用项目规则 |
| 写作方向选项 | 更新已有方向字段 | 是否重建草稿、是否提示覆盖，沿用现有逻辑 |
| 顶部返回图标 | 查清当前项目中该按钮的绑定再接入 | 单靠外形不能确定它是返回上一页、回到开头还是回看 |
| 菜单 | 打开既有菜单 | 不引入一套新的菜单流程 |

以下是可映射的概念字段，不要求新建数据库或修改现有业务结构：

```text
selectedDirectionId          当前写作方向
availableDirections          当前可用方向列表
selectedMaterials            当前素材列表
materialLimit                从配置读取；参考图显示 10
coveredParagraphCount        根据当前选材结果计算
requiredParagraphCount       从现有逻辑读取；参考图显示 4
articleTitle / articleBody   当前可编辑稿件
validationIssues             现有校验结果
isGenerating / isSubmitting  已有异步状态
canPreview / canEdit / canSubmit  使用现有业务条件计算
```

`Not ready yet`、`Direction selected`、`Some paragraphs still empty` 不能无条件固定显示。根据真实状态决定文案和勾选；素材数与段落覆盖数分别更新，不把两者混为一个进度。参考图没有展示完成态、选中第二方向、素材卡列表和加载态，不能声称这些美术已包含在包中。

| 切换选中方向 | `06` 第一项选中状态已烘焙；`09/10` 尺寸也略有差异 | 先制作去掉选项内框和勾号的干净方向面板，再用同尺寸状态皮肤；不能仅移动一个勾号 |

| 三个状态圆圈切为完成态 | 空圆圈已烘焙 | 可在同一个圆圈中心叠小勾，但需检查线条是否协调；若要替换圆形底，应先补干净底板 |
| 修改步骤编号 | 底图保留无字红圆 | 直接动态写数字即可 |
| 清除状态区右下角装饰 | 装饰与底图不可分离 | 补干净底板，不能只隐藏独立 `clipboard_pen.png` |
| 按钮 hover / pressed / disabled | 只提供静态按钮素材 | 可先用轻微缩放、透明度或颜色乘算作临时反馈，并明确不属于已提供的完整状态美术 |
| 精确还原全部场景边缘 | 无独立场景背景；纸板与部分图标为补绘 | 复用原项目场景，接受并记录局部差异，或补原始分层素材 |
| 任意比例拉伸与九宫格 | 未制作或验证九宫格 | 先等比缩放；需要九宫格时单独确认边界并验证纸纹、阴影和圆角 |

不要把含纸纹的局部裁片当作透明图标随意挪动，否则容易出现矩形色块或纹理接缝。当前包可以搭建初始界面，但完整动态界面应先处理上述烘焙状态。

## 10. 给 AI 的执行顺序与交付检查

1. 找到项目当前编辑台页面、对应逻辑和素材目录，确认现有引擎、坐标约定和文本组件。只改相关界面。
2. 导入素材并保留目录或建立明确映射。确认 PNG Alpha、色彩与纹理导入设置，不自动裁边；文字图片避免有损压缩。
3. 建立 1678 × 937 虚拟根节点，先按第 5 节摆完整面板和按钮。不要一次放入全部 25 个裁片。
4. 加入文字与点击区域，核对所有标签、数字、图标是否只出现一次。
5. 对照第 9 节列出动态状态所缺底图；在对应缺口解决前，不将该功能标记为完成。
6. 绑定项目原有数据和事件，测试选材返回、预览、编辑、审核及异步错误恢复。不得用参考图计数替代真实数据。
7. 在参考比例截图对照，再至少检查一个宽屏窗口和一个较小窗口。确保按钮不越界、文字不被裁切、正文滚动不带走来源栏。
8. 向用户说明实际改动、已验证交互和仍缺的素材；不要将本说明中的建议位置或字号表述成原工程精确参数。

验收时重点检查：同名有字/无字切换不位移；勾号和图标不重复；纸张接缝不明显；动态计数正确；文本层不挡点击；未就绪与加载时的提交行为符合已有规则。
