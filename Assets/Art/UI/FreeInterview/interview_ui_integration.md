# 自由采访 UI 接入说明

本文供接入界面的开发 AI 使用。目标是按已确认的木桌、纸张拼贴风格还原自由采访界面，并让角色、对话、问题与状态数值由现有系统驱动。

**先读现有工程，再替换表现层。不要重写采访规则、角色逻辑或请求接口。不要把示例文字、固定角色图或固定状态值重新画进 UI。**

## 2. 设计画布与坐标约定

以本次确认的完整效果图 **1675 × 939** 为参考画布，横向布局。以下坐标是依据效果图整理的接入建议值，不是从原工程读取的布局参数，也不是严格的逐像素还原数据。拆出的图片经过生成式编辑，外形与比例存在细微差异，需要在组装后做视觉对照。

- 原点在画布左上角，X 向右，Y 向下。
- `x, y, w, h` 均为参考画布中的像素。
- **坐标描述组件的可见美术范围，而不是包含大片透明留白的 PNG 外框。**
- 单个组件图片中已经带有的倾斜、胶带和纸夹属于美术本身，控件不再额外旋转。
- 图标、纸夹和照片框保持比例；可伸缩纸条按后文规则处理。

对不同窗口尺寸，优先使用统一比例缩放，保留三栏关系。基础计算为：

```text
s = min(viewportWidth / 1675, viewportHeight / 939)
offsetX = (viewportWidth  - 1675 * s) / 2
offsetY = (viewportHeight - 939  * s) / 2

screenX = offsetX + designX * s
screenY = offsetY + designY * s
screenW = designW * s
screenH = designH * s
```

背景可以铺满整个窗口，交互内容放在完整可见的设计区域内。宽屏时不要把文字横向拉长；窄屏时不要直接裁掉左右栏。如果现有工程已经使用 1920 × 1080 等设计分辨率，将这里的参考坐标整体映射过去，不要同时保留两套重复缩放。

## 4. 左侧照片：底图与角色分离

使用 `dynamic/01_photo_background.png` 作为固定底图。图片内的棕色区域是保留的照片背景，米白下边框已清空；外部为透明。**不要再使用带大福的旧照片卡，也不要将角色画入底图。**

角色图单独放在照片底图之上，由当前受访角色或系统表情状态决定。默认沿用工程已有的角色素材，不要重新生成大福或擅自改变角色脸型。

建议在照片可见范围内，以左上角为局部原点，建立一个大致覆盖棕色内窗的四边形裁切区。归一化顶点初始值如下：

```text
左上 (0.062, 0.103)
右上 (0.860, 0.044)
右下 (0.912, 0.631)
左下 (0.108, 0.683)
```

以上为对当前照片美术的近似描点，组装时沿实际棕色内窗微调。角色保持比例、底部居中，不遮盖白框或胶带；可从照片局部范围 `(0.16, 0.16, 0.66, 0.49)` 开始摆放。角色图片本身的透明留白也要计入处理，避免视觉上过小。

米白下边框可以承载系统提供的角色名与简介。若当前系统没有这些信息，就保持留白，不要自动补回 DAFU 或示例描述。


### 长条纸张如何适应高度

纸条的左右纸边和姓名标签不应随正文整体拉伸。优先沿用工程已有的九宫格或分段伸缩方式，固定纸边，只扩展中间可写区域。切片位置必须在去除透明外边距之后确定，不能拿原始 PNG 尺寸直接切片。超长消息可分段显示，但不要改写系统正文。

### 动态填充逻辑

三条填充图都是 100% 满格，不代表默认状态。先将各自可见区域映射到空槽内部的统一尺寸，再按数值从左向右裁切。不要按当前比例压缩整张彩条，否则纹理和圆角会被挤变形。

```text
if maxValue <= minValue:
    使用现有系统定义的无效范围处理方式，不进行除法
else:
    fraction = clamp((value - minValue) / (maxValue - minValue), 0, 1)

显示区域宽度 = 槽内宽度 * fraction
彩条的满格绘制宽度始终等于槽内宽度
```

状态范围从现有系统读取，不要默认所有状态都是 0–100，也不要把之前图片中的 55、15、80 写为固定初始值。Pressure 增大时，红条长度也随实际数值增大；除非现有设计已有约定，不要自行反向显示成剩余安全值。

填充层需要缩进空槽边框内。以当前 178 × 25 的显示槽为起点，可先使用四周约 2 设计像素的内边距，再根据效果微调；由圆角遮罩保证彩条不盖住外侧铅笔边。0% 时不残留彩色圆头，100% 时不露出不应出现的末端空白。

## 8. 输入框与固定按钮

`dynamic/06_question_input_blank.png` 仅负责底图，必须在其上放置真正可输入的控件。建议文本输入区域约为全局 `(461, 796, 631, 49)`，避开左侧胶带。可以将现有 placeholder 放在文本层，不能再使用旧的带 Type your question… 的输入框图片。

Send 调用现有提交入口。空内容不提交；请求期间应沿用项目的防重复提交规则。中文输入法正在组词时，不要因 Enter 提前发送。换行与发送快捷键遵循工程现有约定。

Review、Notes、Menu、End Interview 分别绑定现有功能。不要仅让它们有图片而无法点击，也不要为演示按钮虚构新的数据。若结束采访已有确认流程则保留；若原工程没有，不要仅因换美术强加额外步骤。

等待回复、提交失败等信息以玩家能够理解的短文本呈现。调试日志和 API key 提示不应出现在采访纸面上，更不能把密钥等开发配置放入可见文本。离开采访后到达的旧响应，不应更新另一个角色或新会话的界面。

按钮点击范围围绕按钮实际可见区域设置，可以适度增加容错范围；不能直接使用包含大片透明留白的完整 PNG 作为按钮范围。装饰图片不参与点击判定。

## 9. 透明留白与精灵裁切：接入前必须处理

多张 PNG 的透明画布远大于可见素材。如果把整张 2172 × 724 的图片直接塞进一个长条控件，视觉尺寸与点击位置都会不对。

建议在导入时使用精灵裁切矩形，或生成独立的裁切派生文件；保留原始 PNG。以下区域通过检查 PNG 的 Alpha 通道得到，阈值为 Alpha ≥ 32。它们是定位可见主体的起点，不是必须硬切掉一切低透明边缘的要求。为保留轻微纸边，可在四周留 2–4 个源图像素的安全边距。

坐标为 `[left, top, right, bottom]`，右边与下边不包含在区域内。不要误读成 `[x, y, width, height]`。

- 必须按 Alpha 通道显示透明，不能根据黑色或白色颜色抠图。透明像素的 RGB 值可能仍含颜色，忽略 Alpha 会出现黑底或光晕。
- 有些素材的主体 Alpha 最大值为 254，不能把“只有 Alpha=255 的像素才有效”作为判断条件。
- 望远镜两个镜片孔应透出背后的底板，不应填成白色。
- 三条填充图的画布和可见比例不同。先分别处理透明外边距，再映射到同一个槽内范围；不要直接共用整图 UV 或未经换算的裁切矩形。
- 上述源图裁切坐标以左上角为原点。如果引擎使用左下角原点，矩形换算为：`x=left`、`y=imageHeight-bottom`、`w=right-left`、`h=bottom-top`。
- 新生成或重新导出的素材可能改变尺寸。文件一旦替换，应重新计算可见区域，不能继续盲用本表。

## 10. 字体、颜色与视觉一致性

动态文本使用工程已有且获准使用的字体。当前效果图里的文字来自图片生成，不应声称已识别出它的精确字体。正文选择清晰、与深棕衬线标题协调的字体；姓名与注记可以使用既有的手写字体，但不能牺牲长文本可读性。

动态文字可从深棕色 `#4B2D1B` 开始调整；这只是接近效果图的建议色，并非源图中唯一的标准取色。状态填充直接保留素材本身的颜色，避免再次用不透明色覆盖掉蜡笔纹理。不要给全部纸张叠加新的厚重阴影、亮边、现代圆角面板或默认系统按钮样式。

若界面包含中英文，检查字体回退后仍能完整显示；不能因为缺少字形而丢字。背景美术和文字分开渲染，窗口变大时文字仍应清晰。

## 11. 接入顺序与完成标准

按下面顺序实施，避免只拼成一张静态截图：

1. 找到现有采访界面、角色数据、状态更新、历史消息、推荐问题、发送入口与四个功能按钮的绑定位置。
2. 导入两套素材并处理透明外边距；明确停用旧的带动态内容组件。
3. 先摆背景、主纸张与左右底板，对照第 3 节检查三栏比例。
4. 接入独立角色图、动态消息、问题文本、输入控件与三个动态状态条。
5. 保持原有请求、会话与按钮行为；清理残留的临时 UI 和调试文本。
6. 用实际会话走一遍，再检查长内容、不同角色与不同窗口尺寸。

交付前至少确认：

| 场景 | 应有结果 |
| --- | --- |
| 换角色或表情 | 只更新独立角色图，不替换整个照片框 |
| 空会话 | 无示例台词、无固定大福文字、无调试信息 |
| 长姓名与长回复 | 姓名和正文不越过纸边，消息高度正确，滚动可用 |
| 玩家查看历史时收到回复 | 不强制打断其滚动位置 |
| 推荐问题更新或数量变化 | 更新实际列表，无旧问题残留，无固定序号图 |
| 状态到最小、最大及中间值 | 长度正确；三个颜色统一槽内尺寸；不显示固定数字 |
| 使用中文输入法 | 组词确认不误触发送 |
| 连续点击发送或网络失败 | 沿用原有提交保护与错误处理，没有重复会话内容 |
| 结束后收到迟到响应 | 不污染新会话或别的角色 |
| 窗口缩放 | 左右栏、输入框、按钮仍完整可用，图标未被压扁 |
| 点击纸张、胶带、透明留白 | 装饰不挡住输入与按钮，按钮命中范围合理 |

完成后向用户说明修改了哪些界面文件、动态内容接到了哪些既有数据，以及仍缺少哪些资产。若没有访问实际工程，只能提供集成方案，不能声称已完成游戏接入。
