## 一、项目概览

- 名称：《街角专访》（Street Cat Interview）
- 引擎：Unity，C#，运行时 UI 基于 uGUI + TextMesh Pro
- 类型：叙事调查 / 采访 / 写稿游戏
- 当前内容：第一章完整竖切流程
- 核心循环：调查收集情报 → 自由采访 → 整理素材卡 → 撰写报道 → 主编审核 → 后日谈反馈
- 特色设定：玩家扮演记者，可以借助「喵语翻译器」采访猫咪，再与人类采访对象的说法交叉验证

第一章路径：

新游戏 → 杂志社剧情 → 槐安社区调查（投喂点、快递柜）→ 与保安交谈 → 等待大福 → 采访大福 → 找到林女士 → 采访林女士 → 选材写稿 → 审核发布 → 后日谈

## 二、核心设计原则

项目最值得强调的一点是：**规则系统负责事实，界面和可选大模型只负责表达。**

- 情报、素材卡、禁用内容、审核结果，全部由离线规则决定。
- `LlmClient` 是可选的 OpenAI 兼容接口，只用于润色规则引擎已经给出的回答。
- 大模型不能新增情报，不能解锁素材卡，也不能临时生成新剧情。
- 因此游戏在无网络时也能完整运行，每条可发表的事实都能追溯到采访或调查来源。

## 三、重点技术案例

### 案例 1：自由采访规则引擎

**要解决的问题**

玩家可以输入自由问题，但调查类游戏需要严格控制「角色知道什么」「什么时候说出关键事实」。完全交给生成式模型，会出现剧透、编造事实和不可复现的解锁结果。

**设计**

- 抽象基类：`InterviewRuleEngine`
- 角色实现：`DafuRuleEngine`（猫）、`LinRuleEngine`（救助者）
- 控制器：`InterviewController`
- 回复模型：`InterviewReply`，包含回答文本、意图、解锁情报、信任 / 压力 / 专注变化、系统提示等

**`InterviewRuleEngine.Process` 的处理顺序**

1. 空输入：返回「没有理解」和输入提示。
2. 敌意输入：走单独处理，降低信任、增加压力、降低专注。
3. 短确认（如「嗯」「知道了」「ok」）：作为追问处理。
4. 普通问题：先用 `InterviewLoc.CanonicalQuestion` 归一中英文问题，再交给具体角色的 `Classify` 做意图分类。
5. `BuildReply` 根据意图和角色知识边界生成回答。
6. 同一意图重复提问：返回重复回答，额外增加压力、降低专注，并清空本次本应获得的情报。
7. `stats.Apply` 结算信任、压力、专注。
8. `PostProcessReply` 做角色专属后处理。

**角色差异示例**

大福是猫，规则引擎会限制它反复谈食物：最近 5 句中，提到食物的回复最多 1 次，超出时把含食物的台词替换为其他内容。这样猫的表达仍有特点，但不会变成只会谈吃的。

**和后续系统的衔接**

- 规则引擎确认获得情报后，`MaterialUnlockTable` 根据情报解锁素材卡。
- `InterviewMaterialExtractor` 为新解锁的素材写入带来源引语的「已确认笔记」。
- `RuleBasedInterviewHintProvider` 根据三项状态、上一句回答、已问过的意图和问题、笔记中未完成的主题，生成教练提示和最多 3 个提问芯片。已经问过的芯片会被替换。
- 提示系统通过 `IInterviewHintProvider` 接口隔离，将来可以替换为其他实现，而不改采访规则。

**可提炼的结果**

- 采访内容可复现，可测试，不依赖联网。
- 玩家仍然能自由输入，但关键事实的解锁受到角色知识边界控制。
- 生成式模型被限制在「润色」层，降低了编造和剧透风险。

### 案例 2：素材卡写稿与规则审核

**要解决的问题**

如果写稿只是把采访文本拼起来，玩家的选材和报道角度就没有意义。系统需要判断「这篇稿件选了哪些证据、讲的是什么主题、是否偏题」。

**设计**

- 素材库：`MaterialCatalog`，第一章共有 M01～M16 十六张固定素材卡。
- 每张卡包含：编号、标题、类型、所属文章阶段、事实正文，以及两套成稿表述。
- 素材类型：事实、细节、情感。
- 两个写作方向：
  - 「从流浪猫到社区保安」（现在的大福）
  - 「一次没有以收养结束的救助」
- 文章结构固定为四段：
  1. 现在的大福
  2. 受伤与救助
  3. 治疗与抉择
  4. 回到社区

**实现逻辑**

- `ArticleAssembler.CanAssemble` 校验：
  - 至少选择 1 张卡，最多 10 张；
  - 四个段落各至少有 1 张卡；
  - 不强制玩家选择某一张特定的卡。
- `Assemble` 根据所选写作方向，从每张卡中取对应版本的句子组成稿件。
- `ApplyRuleReview` 根据选材分布做规则审核：
  - 例如选择救助方向，却放入过多现状素材，或缺少放归相关内容，会退回；
  - 选择现状方向，却过多偏向受伤、手术和救助过程，也会退回；
  - 通过条件为分数不低于 70 且审核分支为 A。
- 玩家之后可以在写稿台修改成稿中的关键表述，但不会让系统临时生成新的事实。

**可提炼的结果**

- 选材本身成为玩法，而不是单纯的收集。
- 写作方向决定叙事框架，素材卡提供证据，审核规则判断稿件是否跑题。
- 所有成稿内容都来自已解锁素材，避免无来源事实进入报道。

### 案例 3：记者笔记系统

**要解决的问题**

自由采访容易让玩家不知道下一步问什么，同时采访结果也需要整理成可写稿的线索。

**设计**

- 脚本：`ReporterNotebook`
- 第一章分为 6 个主题：
  - 大福的社区生活
  - 过去的大福
  - 脖子上的伤
  - 大福的救助者
  - 被带走以后
  - 大福的回归
- 每个主题有未完成 / 部分完成 / 完成三种状态。
- 获得情报后，笔记更新对应主题状态。
- 采访问答会关联到对应主题。
- 笔记只给出当前最值得追问的一条灵感，避免直接给玩家完整答案。

**可提炼的结果**

笔记把调查、采访提示和写稿选材连成一条线：它既是玩家的进度提示，也是采访系统判断下一步提问方向的依据。

### 案例 4：Play 模式可视化编辑工具链

**要解决的问题**

项目的大量运行时 UI 是用代码生成的，不依赖预制体。这样方便和游戏状态联动，但调整布局、字号、热点区域和对白文本时，需要反复改代码、重启 Play，效率很低。

**设计思路**

在 Play 模式中直接操作 Game 视图，修改后自动保存到对应的数据资产或 JSON 文件。不同类型的数据分开存放，避免一个通用工具覆盖专用系统的布局。

**主要工具**

| 工具 | 作用 | 数据保存位置 / 实现要点 |
|---|---|---|
| 通用 UI 布局编辑器 | 在 Game 视图中选择、拖动、四角缩放 UI 控件；支持方向键微调、撤销和删除 | 保存到 `UILayoutOverrides.asset`；选中控件后会锁定当前对象，防止误点其他控件，按 L 解除 |
| 调查热点编辑器 | 在调查地图上拖动、缩放可点击热点 | 保存到 `InvestigateHotspotLayout.asset` |
| 社交帖子、标题菜单、立绘布局编辑器 | 分别调整手机帖子、标题界面、角色立绘位置 | 各自使用独立布局数据，不进入通用 UI 覆盖表 |
| 对白文本编辑器 | 在 Play 中按场景和行号修改当前语言的对白 | 以 `sceneId:lineIndex` 为键；中文写入 `scripts_overrides_zh.json`，英文写入 `scripts_overrides_en.json` |
| 字体与字色工具 | 调整对白和 UI 文字样式 | 中英文分别保存字体、字号、字距；提供「清除已锁死的文字尺寸覆盖」，修复旧布局数据导致设置滑杆失效的问题 |
| 图片清晰度体检 | 扫描 `Assets/Art` 与 `Assets/Resources` 中的贴图导入设置 | 检查块压缩、最大尺寸小于原图、平台覆盖设置、缩放 UI 使用点采样等问题；可只出报告，也可批量改为无压缩或高质量压缩 |
| BGM 响度、TMP 字体烘焙、调试跳转 | 支持音量调整、字体资源生成、快速跳到调查 / 采访 / 写稿等流程 | 用于减少重复测试成本 |

**保护机制**

`UILayoutOverrides` 会跳过部分有专门数据源或系统用途的节点，例如：

- 全屏遮罩和系统层；
- 社交帖子层；
- 调查热点层；
- 自由采访界面；
- 舞台立绘。

这样可以避免通用编辑器保存的位置覆盖专用编辑器或代码布局。

**可提炼的结果**

- 让策划和美术可以在运行中直接调整画面，而不必改 C#。
- 把「运行时生成的 UI」和「可视化调参」结合起来。
- 用数据隔离和路径保护，减少多套布局数据互相覆盖的问题。

## 四、可以简要提及的技术点

### 中英文本地化

- 界面文本：`ui_zh.json` / `ui_en.json`
- 固定剧本：`ScriptLoc`，按 `sceneId:lineIndex` 覆盖
- 硬编码调查、对话和笔记文本：`HardTextLoc`
- 中文 C# 源文本作为权威底稿，英文作为覆盖层。
- 中英文字体、字号和字距分别保存，避免拉丁字体渲染中文时缺字。

### 剧本导入

- 原始剧本为 docx。
- `Tools/import_chapter1_script.py` 将剧本导入到 `BuiltInScripts.cs`。
- 旁白、内心独白、系统文本、立绘表情等会映射为不同的 `LineSpeaker` 或立绘字段。
- 自由采访场景不写入固定对话树，避免剧本示例与规则引擎冲突。

### 美术接入

- 使用无字 UI 底板，文字、数字和状态由游戏逻辑动态填写。
- `VnArt` 负责从 `Resources/VnArt` 加载并缓存美术资源。
- 自由采访界面会根据接入说明裁掉 PNG 的透明边，避免纸张在控件里显得过小。
- 不把完整效果图直接贴到界面上，而是拆成可复用的组件。
